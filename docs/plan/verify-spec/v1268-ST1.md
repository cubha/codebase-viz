### VERIFY-SPEC — SubTask ST1 (Prisma @@map/@map + 센티넬)

- 기준선 요구사항: "Prisma `@@map` 미처리 → 틀린 테이블명 노출" 수정 + ORM 클래스 센티넬.
- 변경 파일: `packages/core/src/db/prisma-parser.ts` (+test)
- 관찰 가능한 계약: `@@map("x")` 모델 → `name='x'`, `id=makeNodeId('table', relPath, 'x')`. 필드 `@map("y")` → 컬럼명 y.
  `inferenceChain = ['prisma: model <Model> in <file>', 'orm-class:<Model>']`(센티넬은 [0] 아님).
- 구현 결정:
  - 필드 `@map`은 기준선 문구엔 없지만 **같은 결함 클래스**(DB 실제 이름과 다른 이름 노출)라 함께 처리 — PLAN에 명시.
  - 노드 id를 모델명→테이블명 기준으로 바꿨다(JPA 파서와 동일 규약). `@@map` 모델만 id가 바뀐다 → ANALYZER_VERSION 범프(ST4).
  - `readMapName`은 `"x"`·`name: "x"` 두 인자 형태를 처리. 따옴표 없는 값(파싱 이상)은 undefined → 원래 이름 폴백.
- 인접 경계: Supabase `.from('tb_account')` 쿼리 엣지가 테이블명으로 매칭된다면 `@@map` 수정으로 매칭이 **새로 성립**할
  수 있다(개선 방향). Prisma는 relation 필드를 컬럼에서 제외하고 FK references를 만들지 않는다(기존 동작 유지).
- 미확인 사항: 쿼리 엣지가 TableNode를 이름으로 찾는지 id로 찾는지(=@@map 모델의 기존 쿼리 엣지가 끊기는지 새로
  이어지는지) 코드로 추적하지 않았다. `@map(name: "x")` 형태의 prisma-ast 출력 구조는 실측하지 않고 추정으로 처리했다.
