### VERIFY-SPEC — SubTask ST7 (Flyway 누적 반영)

- 기준선: 로드맵 미등재 잔여 "Flyway `ALTER TABLE` 미지원"(결함 일괄 수정 요청).
- 변경 파일: `packages/core/src/db/flyway-parser.ts` (+test)
- 관찰 가능한 계약: 파일 = 버전 숫자 순. 파일 안 문장 순서대로 CREATE/ALTER 적용. ALTER: ADD [COLUMN] [IF NOT EXISTS] / DROP [COLUMN]
  [IF EXISTS] / RENAME COLUMN a TO b / ADD [CONSTRAINT x] FOREIGN KEY. CREATE의 인라인 `REFERENCES t(c)`·테이블 레벨 FOREIGN KEY →
  `references`. 그 외 ALTER(타입 변경·UNIQUE·인덱스·DROP CONSTRAINT)는 무시.
- 구현 결정: 문장 분리 = 주석 제거 후 `;` 단순 split — 문자열 리터럴 안 `;`(예 `DEFAULT ';'`)는 문장을 잘못 자른다(드묾, 미대응).
  복합 FK는 첫 컬럼 쌍만. 선언 라인은 주석 제거 전 원문에서 재탐색.
- 인접 경계: `mergeFlywayTables`는 ORM 우선 — ORM 테이블에 이미 있는 컬럼은 Flyway references가 붙지 않는다(기존 규칙).
- 미확인 사항: `R__` repeatable·`U__` undo 마이그레이션은 파일 패턴상 원래 제외. 실 Flyway 레포 실측 없음.
