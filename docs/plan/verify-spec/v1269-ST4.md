### VERIFY-SPEC — SubTask ST4 (Angular 라우트 결함)

- 기준선: "Angular forChild 등 결함은 없어야하는거니까.. 결함내용도 이번에 같이 수정" + 재실측 손실 지점.
- 변경 파일: `packages/core/src/adapters/angular/parsers/route-parser.ts` (+test)
- 관찰 가능한 계약:
  ① `loadChildren(m => m.XModule)`(NgModule 클래스) → 그 모듈 `@NgModule` 데코레이터의 `RouterModule.forChild` 배열, imports의
     라우팅 모듈(`AdminRoutingModule`)까지 depth≤3 추적. 부모 prefix 부여.
  ② lazy로 마운트된 배열은 forChild 단독 처리에서 제외(2단계: 루트 펼침 → 미마운트 forChild만).
  ③ 경로 join 정규화(후행·중복 슬래시 제거).
  ④ 엔트리별 componentSpec·loadComponent·선언 파일 보유 → lazy 하위도 컴포넌트 파일 매핑.
  ⑤ fullPath 키 Map 폐기 → 같은 path 덮어쓰기 없음. named outlet은 NodeId 심볼에 `(outlet)` 부가. 같은 id는 1회만.
  ⑥ 컴포넌트 없는 컨테이너(children/loadChildren)는 자식에 기본 outlet `path:''`가 있으면 따로 내지 않음(그 자식이 같은 URL 페이지).
  ⑦ `redirectTo` 전용 항목은 라우트 아님.
- 구현 결정: provenance가 "라우터 호출 파일:호출 라인" → "라우트 객체 선언 파일:객체 라인"으로 바뀜(lazy 하위가 엉뚱한 파일을
  가리키던 딥링크 결함의 같은 원인이라 함께 정정). Angular 노드 id 변경 → ANALYZER_VERSION 범프(ST8).

  주석·`>=4` → 정확히 4.
