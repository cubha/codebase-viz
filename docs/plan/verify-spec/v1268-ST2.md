### VERIFY-SPEC — SubTask ST2 (TypeORM 센티넬 + FK 테이블명)

- 기준선 요구사항: "TypeORM/Drizzle이 클래스/변수명을 쥐고도 센티넬을 안 싣는다" + (PLAN) FK가 클래스명을 참조하는 결함.
- 변경 파일: `packages/core/src/db/typeorm-parser.ts` (+test)
- 관찰 가능한 계약: 엔티티마다 `orm-class:<ClassName>` 센티넬(배열 뒤). 관계 컬럼 `references.table`은 스캔된
  엔티티면 **대상의 테이블명**(`@Entity('tb_member') class Member` → `tb_member`), 스캔 범위 밖이면 클래스명 폴백.
- 구현 결정:
  - JPA 파서의 `classToTableMap`과 같은 선행 패스. RED 테스트로 결함 실증(`'Member'` ≠ `'tb_member'`) 후 수정.
  - 폴백을 남긴 이유: 기존 테스트 2건(대상 엔티티가 스캔 밖)이 클래스명 참조를 기대 — 알 수 없는 대상은 추측하지 않음.
  - 익명 클래스(`getName()` undefined)는 센티넬 생략.
- 인접 경계: ERD `db-diagram.ts`는 FK 선을 `tableNameSet.has(sanitizeId(references.table))`일 때만 그린다 → 이번 수정으로
  TypeORM FK 선이 **새로 나타난다**(`@Entity()` 무인자도 소문자화로 클래스명과 달라 이전엔 드롭됐음).
- 미확인 사항: 클래스명이 여러 파일에 중복 선언된 경우(동명 엔티티) 마지막 선언이 이긴다 — 결정론적이지만 검증 안 함.
